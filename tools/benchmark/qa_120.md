# 1.2.0 QA: does the Verdict tell the truth? (2026-10-25)

Scanner: APKReLab 1.2.0 sources (commit bd756e6 + the sandbox reach line), run with `tools/sandbox/SandboxScan.kt` (the app's Kotlin pipeline without the UI). Reports and decoded classes in `./private/qa120/` (not committed).
Sandbox limits that matter for the Verdict: no device reach pass for RULE cards (only SSA cards get reach labels, from the engine's call graph), no AI triage, no strings overlay, no splits; Nextcloud ran with `nossa` (54,323 classes: the device would group it; its taint cards here come from the class-level rule).
Every HIGH / CRITICAL card below was read in the smali / manifest. "Y/N" columns judge the Verdict line against the code; an "N" names its cause.

## Blocked (no row can be filled honestly)
- **Group A** (VulnLab, DVFA, VBank, Gu3ssWeak, Beetlebug) and **Vuln-Bank-Mobile** (Group B): their APKs are GitHub release assets. This session gets GitHub per repository: `github.com/<owner>/<repo>/releases` answers 403 ("GitHub access to this repository is not enabled for this session"); anonymous `git clone` of public repositories works, but release assets are not in git. Not worked around (no mirrors, no APK hunting inside clones).
- **Group D** (self_check on Sieve, Allsafe, PIVAA, Vuldroid, OVAA, InsecureShop): the six APKs are not in `./private/` and come from the same GitHub releases. No recall number is reported for 1.2.0; the script was validated earlier on fixtures and on the frozen 0.75.1 device reports (Sieve 8/8, Allsafe 6/7: 0.75.1 numbers).

## Group B: NOT SEEN against what the scanner did (one line per app)
- KeePassDX: "native: 7 native methods, flows into .so not followed, 2 libraries read" = NativeBridge: 7 declarations, 7 static JNI exports in libaes.so / libargon2.so; no taint is followed into native code (1.1.0 decision). Honest.
- NewPipe: no decryptor, no native method outside the androidx graphics library (8 in total, 1 library read), whole app in one run. Honest. The Verdict costs 0.05% of the scan.
- Flutter / React Native (stand-ins): honest only after the fix above.
- Premise corrected: "assets: JS bundle not scanned (until D1)" - D1 exists since 0.103.0 (AssetScanner reads JS bundles and Hermes string tables as text). What is not analysed is the JS / Dart CODE, which NOT SEEN now says.
